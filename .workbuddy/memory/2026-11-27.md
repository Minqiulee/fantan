# 2026-11-27

## 席位号改为非连续清单（1/2/3/5/6/8）

把「席位号 = 1…seatCount 连续」改成「席位号取自 `lib/seats.js` 的 `SEAT_NOS` 清单前 N 项」。
门店现场可用座位编号是 1、2、3、5、6、8（4、7 号位不存在）。

- `lib/seats.js`：新增 `SEAT_NOS = [1,2,3,5,6,8]`、`seatNosFor(count)`（清单前 N 项，超出长度按未占用正整数顺延补号），`DEFAULT_SEAT_COUNT = SEAT_NOS.length`（仍是 6）。
- `db.js`：`createSessionRow` 物化由 `generate_series(1, n)` 改为 `unnest(seatNosFor(n))`；`rowToSession` 按清单铺满，库里清单外的行只保留「有设备绑定」的（老编号席位不丢，空席位忽略）；去掉 `no > seatCount` 的过滤。
- `server.js`：`/api/join` 越界判断从 `asked > seatCount` 改为「快照里有没有这个席位」（号不连续，不能靠号段推断）；`/api/session-seats` 扩缩容改为按目标清单对齐，缩容拒绝条件从「小于最大已占用号」改为「目标清单里不含任何已占用席位」（错误码 `seat_count_below_occupied` 与 `maxOccupied` 字段保留）。
- `public/shared/i18n.js`：席位设置弹窗三语文案改为「已占用的席位不能缩出范围」。
- 测试：`test/seat.test.mjs` 默认席位断言改为 `[1,2,3,5,6,8]`，涉及 4 号的用例改用 5 号（4 人场次的清单是 1/2/3/5）。
- README：6.1、6.1.1、数据模型、测试说明、容量说明同步为清单口径。
- 验证：`npm test` 112 用例全过；临时 Postgres 实测 `session_seat` 落库为 1,2,3,5,6,8。
- 迁移注意：升级前已开的场次若有人占着 4/7 号，该席位会保留（有 device_id 的行不丢），但该场次再调人数会被 409 挡住，需要关闭后新建场次。
