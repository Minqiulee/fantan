# 2026-11-17

## 玩家端扫码界面：新增「切换摄像头」按钮

改动文件：`public/index.html`、`public/i18n.js`（zh-CN / zh-HK / en-US 三套文案）

实现要点：
- `#camBox` 加 `position:relative`，按钮 `#camSwitchBtn` 绝对定位在取景框右上角（38px 圆底 + 金色图标 + 毛玻璃）。
- 未引入新的相机库：仍用本地 `html5-qrcode.min.js`。切换 = 停掉当前实例 → 用 `{deviceId:{exact:id}}` 重建实例重启，解码回调复用同一套逻辑。
- 新增实例序号 `camSeq`（token）：停止/重启时递增，`onDecoded` 校验 token，丢弃旧实例的迟到回调，避免切换瞬间误触发扫码。
- 摄像头枚举走 `navigator.mediaDevices.enumerateDevices()`（不额外触发权限弹窗），启动成功后用 `track.getSettings().deviceId` 反查当前镜头下标；标签含 back/front 关键字时优先切到相反朝向，否则按顺序轮换。
- 多摄像头才启用按钮；单摄像头/枚举失败 → 按钮禁用（半透明）+ 一次性 toast 提示；相机未开时按钮隐藏。
- 切换失败自动回退原镜头，保证扫码不中断；记住上次选中的 deviceId，重开相机沿用。
- 修掉一个隐患：`startScanner` 启动失败时必须复位 `camActive`，否则后续重试会被 `if (camActive) return` 挡住。

验证：Playwright + Chromium 假摄像头（`--use-file-for-fake-video-capture` 生成带二维码的 y4m）。覆盖多摄像头切换、切换后仍能识别二维码、切换失败回退、单摄像头禁用提示，均通过。

## 后续调整：默认改为前置摄像头

- 新增常量 `DEFAULT_FACING = 'user'`，`startCamera()` 每次打开都用前置启动（`facingMode: 'user'`，ideal 语义，单摄设备不会因此报错）。
- 取消「记住上次镜头」的跨次记忆：`camDeviceId` 只服务当次会话的切换流程，重新打开一律回前置。用户手动切到后置只影响本次。
- `facingMode` 拉流失败（OverconstrainedError / NotFoundError）时退回不带约束再试一次，仍失败才提示。
- 验证：拦截 `getUserMedia` 断言首个约束为 `{facingMode:'user'}`；切换后为 `{deviceId:{exact:...}}`；原有切换/识别/回退/单摄场景全部复测通过。
