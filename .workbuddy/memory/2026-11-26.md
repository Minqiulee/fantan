## VBA JWT 客户端（vba-jwt-client/）

按需求写了 Button3 → 读 TextBox1 明文 → Base64 → 密码签 JWT → HTTP POST 的完整实现。

产出：
- `modCrypto.bas`：纯 VBA 的 UTF-8 / Base64 / SHA-256 / HMAC-SHA256，无 .NET 无 DLL，含 8 项向量自检。
- `modJwtClient.bas`：配置常量、HS256 JWT 组装（claims 带 body_sha256 绑定请求体）、MSXML2.ServerXMLHTTP POST、错误码映射到中文提示。
- `frmUpload_Button3.txt`：窗体事件代码（中文，供粘贴）。
- `README.md`：落地步骤、配置表、故障对照、风险说明。

关键技术决策（以后复用）：
- VBA Long 有符号会溢出 → 用 Double 承载无符号 32 位值，移位/循环右移用 Double 精确算，避免手写 32 位加减。
  RoR 正确写法：`(u \ 2^n) + (u mod 2^n) * 2^(32-n)`，注意是取低 n 位。
- 先用 Python 复刻同一套算法对 hashlib 做 300 组随机比对 + RFC 7515 向量，再落 VBA，能提前抓出公式错误。
- 避免把「函数返回的数组」直接塞进 ByRef Byte() 参数，一律拆中间变量。
- `.bas` 必须纯 ASCII + CRLF：VBE 导入按系统 ANSI 代码页解码，UTF-8 中文会乱码；中文字符串用 `ChrW` 构造。
- `DateDiff("s", #1/1/1970#, d)` 在 2038 年后溢出 Long，改用 `(CDbl(d) - CDbl(#1/1/1970#)) * 86400#`。
- UTC 时间戳用 `kernel32!GetSystemTime`（PtrSafe 条件编译），避免时区偏移错误。

已向用户指出的问题：Base64 不是加密、密码直接当 HMAC 密钥不规范、InputBox 不掩码、客户端持签名密钥的架构局限。
