## 玩家端场次口令 + 场次绑定（第二轮）

### 设计

- **一个统一口令**（`PLAYER_SESSION_PASSWORD`，默认 `8888`），只管「选择 / 切换场次」这一个动作；不是一场一口令（理由与后续方案写在 README 待办第 10 条）。
- 口令只以 **scrypt(口令, 随机盐)** 存在进程内存：不落库、不下发、不进日志。`initPlayerPassword()` 启动时由环境变量重算。
- 验证通过 → 签发**绑定令牌** `ut = sid.exp.HMAC-SHA256(secret, sid.exp).slice(32)`，密钥随机生成存 `app_config.player_bind_secret`，所以**重启后玩家绑定仍有效**。
- 准入统一收口在 `playerSessionContext(sid, ut, staffToken)`：员工 token 直通（不受玩家口令约束）；玩家有令牌以令牌场次为准（改 sid → `session_locked`）；无令牌只在「唯一进行中场次」放行，否则 `session_need_unlock`。
- 客户端 `oe_bind = {sid, ut, exp}` 存 localStorage，不存口令；刷新/重开/多标签都复用；「切换场次」保留当前连接，选场次才弹口令，取消原样退回。

### 踩到的两个真 bug（都是测试逼出来的）

1. `unlockLockLeft()` 在「未锁定」时也会删掉失败计数 → 永远到不了 5 次。改为只在 `st.until` 非 0 时才做过期清理。
2. 取消口令弹层没退出「切换态」（`picking`），导致「切换场次」按钮被隐藏、无法再操作。取消统一 `picking=false; render()`。
3. 还顺手补了一个我自己引入的回归：员工端也走 `/api/state|stream`，多场时会被玩家口令拦住 → 员工侧改为带 `?token=` 放行。
