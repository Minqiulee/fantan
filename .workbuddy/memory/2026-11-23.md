## SSE 观测补齐 + 三项诊断实测（分支 feat/stream-connect-latency-metrics，承接 55b2766）

Matthew 要求「补可观测性 + 实测检测延迟/建连成本/死连接与崩溃面」。结论先行记录：

**实测结果（`node scripts/sse-diagnostics.mjs`，黑洞 TCP 代理模拟静默断链）**
- 静默断链后服务端 **>70s 仍未发现**（连接一直挂在组里）；客户端主动 close 后 **58ms** 回收。检测延迟不可控，根因是心跳单向写 + 客户端无空闲判据。
- 在场玩家重连：`mutate` p50 **2.94ms → 0ms**（只读预检），`total` **6.9ms → 4.4ms**（降 36%，不是数量级——ctx 段占大头）。
- 确有 `left_at` 要撤销时两版都在写库，`mutate` 12.8–13.5ms（真实写事务成本）。
- 6 条半开连接 + 持续广播 60s：`connections` 始终 12、`stalled`/`maxPending` 为 0（写入先被内核发送缓冲 MB 级吸收）；`rss` 在 56–75MB 间波动，**没有单调爬升**。
- **反驳原假设**：对已销毁的 `res` 写入不会让进程退出。Node 22 的 http server 会吞 ECONNRESET；四种情形（afterRst/afterRstBig/afterEnd/afterDestroy）探针均 exit=0。真正的隐患是半开连接上无界的 userspace 待发队列。

**改动**
- `lib/stream-metrics.js`：新增分钟分桶（5 个）、`reconnect`/`lastEventId`（判据=请求头 `Last-Event-ID`，只用于观测）、`waiting`（建连那刻池排队数）、`stages.poolWaiting`、`reconnects{lastMinute,last5MinAvg,*PerMinute}`、`minutes`。
- `server.js`：`sseStats()`（sessions/connections/dead/stalled/maxWritableBytes/opened/closed/peak/groups）+ `memSample()`，挂到 `/api/stream-metrics`；`dropClient()` 统一摘连接；`sseSend` 拒写 destroyed/writableEnded/超 256KB 失速；心跳里检查 `writableLength` 回收失速连接；`res.on('error')`/`req.socket.on('error')`/TCP keepalive；进程级 `uncaughtException`（网络类只记日志，其余退出）+ `unhandledRejection`。
- **只读预检**（关键优化）：`STREAM_PRESENCE_PRECHECK`（默认开），`needsPresenceRevoke()` 与 mutator 判定逐条对齐，没 `leftAt` 就不进写锁；`=0` 可退回旧行为做 A/B。`tMutate` 只在真走写路径时推进，故跳过时 `mutateMs` 精确为 0。
- 客户端 `public/shared/sse-guard.js`：`SseGuard.create(es, {staleMs, onStale})`，默认 25s、检查间隔 staleMs/10（误差 ≤2.5s），三页面（index/staff/bigscreen）接入，收到 `state`/`draft`/`ping` 均 touch；超时 → 显示 connLost + `es.close()` + 重连。
- `scripts/sse-diagnostics.mjs`：`detect|cost|dead|all` 三实验，自带 Docker 临时库（无 TEST_DATABASE_URL 时），产物写 `docs/sse-diagnostics-<date>.txt`（已 gitignore）。
- 测试：`test/stream-metrics.test.mjs` 9→15 用例（重连识别/连接面/只读预检/PRECHECK=0 A/B）；新增 `test/sse-guard.test.mjs`（vm 加载浏览器脚本，钉住「持续有事件不触发 / 空闲触发一次 / stop 取消 / CLOSED 不判」）。
- README §7.1.1 字段表补全，新增 §7.1.2「静默断链：检测、止损与实测」+ 环境变量 `STREAM_PRESENCE_PRECHECK`。
