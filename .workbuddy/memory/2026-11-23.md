## 奖品规则生效逻辑改为「按轮绑定」

需求：规则更新后，同一 session 随后新开的 round 必须应用最新规则，不能沿用开场时绑定的旧版；已在进行的 round 按原规则处理。

改动：
- `server.js` `/api/reset`：mutator 前 `loadLatestRule()` 直查库取最新版，mutator 里 `round += 1` 后重绑 `s.ruleVersion` + `s.rule`。
- `db.js` `commitSnapshot`：`game_session` upsert 补写 `rule_version` 列（此前只在 createSessionRow 写一次，永不更新，导致 reset 的新版本落不了库）。
- 语义从「场次创建时锁定版本」改为「规则按轮绑定」：`game_session.rule_version` 存当前这一轮所用版本，reset 时更新。归档表 `round_archive.rule_version` 已按轮记录，天然兼容对账。

测试：改写 `test/rule-version.test.mjs` 对账用例 → 「新开一轮重绑最新规则」，验证改规则→reset→新一轮按新版判定、归档逐轮可辨。全套 104 测试通过。

文档：README.md 更新了 6.10 节及 31/241/345/355/356/404/563/603/743/763 等处的旧语义描述。

追加（Matthew 要求显式落列）：给 `round` 表新增 `rule_version` 列，作为「当前轮所用版本」的权威来源。
- `db.js`：round 表加列（`ADD COLUMN IF NOT EXISTS`）；`createSessionRow` 插 round 时写首轮版本；`commitSnapshot` round upsert 补写 `rule_version`；SNAPSHOT_SQL 与 listSessionSummaries 的 JOIN 改为 `COALESCE(r.rule_version, gs.rule_version, max(version))`（round 优先、场次兜底）；`pinSessionsWithoutRule` 同时补 round 表版本。
- `server.js` reset 注释更新为「写回 round.rule_version」。
- 测试补断言：round 表 rule_version 列存在且 reset 后 = 最新版。全套 104 测试通过。
- README 更新 game_session/round 表结构描述、6.10 节 JOIN 口径、补列说明（加入 round.rule_version）。

## 席位（seat）配置与加入流程

新增「场次参与人数 = 席位总数」模型，设备首次加入必须选座，跨轮次沿用。

- `db.js`：`game_session.seat_count`（默认 12）；新表 `session_seat(session_id, seat_no, device_id, member_id, member_enc, bound_at)`；`player.seat_no`；`rowToSession` 按 seatCount 铺满座位并叠加库行；`commitSnapshot` 在同一事务/版本锁内同步席位；`createSessionRow` 物化 1…N；`listSessionSummaries` 带 seatCount/seatOccupied。
- `server.js`：新增 `POST /api/session-seats`（扩缩容，缩容不得低于最大已占用席位号）、`GET /api/seats`、`POST /api/join`（首次必选座、已绑定幂等沿用、seat_taken/out_of_range/seat_required）。`/api/scan` 要求 deviceId 且该设备已占席位，写入 `seatNo`；一个会员一轮只能一个席位（`member_other_seat`），一个席位一轮只能一人（`seat_member_conflict`）。`/api/reset` 清玩家与席位会员绑定、保留 device_id；SSE 重连放回名单时同样校验席位占用。
- 前端：玩家端新增选座卡片（`oe_device` + `oe_seat:<sid>` 本地绑定，SSE 实时占用，冲突刷新）；管理端场次条「席位设置」+ 新建场次第二步入参；员工端/大屏显示席位号；三语文案补齐。
- 测试：新增 `test/seat.test.mjs`（5 用例）；helpers `scan()` 自动完成 join+scan 虚拟设备。全套 109 用例通过。Playwright 冒烟：选座、刷新不重选、二设备占用置灰、扫码、admin 缩容拒绝/扩容、staff/大屏席位显示，均无 console error。
- README 更新功能表、6.1/6.1.1、生命周期、玩家状态、API、错误码、数据模型与测试说明。

## 席位默认值收敛到 lib/seats.js

把散在四处的 12 / 1 / 64 收成单一真源。

- 新增 `lib/seats.js`：`DEFAULT_SEAT_COUNT=12`、`MIN_SEAT_COUNT=1`、`MAX_SEAT_COUNT=64` + `isSeatCount` / `parseSeatCount`（严格，非法即 null）/ `clampSeatCount`（宽松，读库兜底，缺失回落默认）。
- `server.js`：常量改为 require 自 lib；`parseSeatNo` 变薄包装 `parseSeatCount`；新增 `serveSeatConfig()` + 路由 `GET /shared/seat-config.js`（下发 `window.SEAT_CONFIG={defaultCount,min,max}`，no-store）。
- `db.js`：DDL `DEFAULT ${DEFAULT_SEAT_COUNT}`；`rowToSession` / `listSessionSummaries` / `commitSnapshot` / `createSessionRow` 的 `12`、`1..64` clamp 全部换常量与 `clampSeatCount`。
- `store.js`：`create({ seatCount = DEFAULT_SEAT_COUNT })`。
- 前端：`public/admin/index.html` 引入 `/shared/seat-config.js`；`admin/app.js` 用 `SEAT_CFG` + `isSeatCountInput()` 替换弹窗预填 `'12'` 与两处 `n<1||n>64`。
- 验证：`npm test` 109 用例全过；临时容器起服务实测 `/shared/seat-config.js` 返回 `window.SEAT_CONFIG = {"defaultCount":12,"min":1,"max":64};`。
- README：功能表、6.1、6.1.1（新增单一定义说明）、容量说明改为引用 `lib/seats.js`。
- 遗留口径：DB 列 DEFAULT 对老库不会自动改（插入总带值，实际不影响）；`test/seat.test.mjs` 仍以字面 12 钉住文档口径。
