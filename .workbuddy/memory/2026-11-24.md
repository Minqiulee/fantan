## 大屏投注盘朝向改为「向心」（围坐观感）

**改了什么**：`public/bigscreen/app.js` 里盘面的旋转从「极角 × 0.5、封顶 ±30°」改成「盘心指向弧心」的径向朝向。

- `RING` 常量：`rotFactor: 0.5 / rotMax: 30` → `rotMax: 72 / bboxDeg: 45`（`bboxDeg` 只用于反推盘宽的包围盒估算，保持和原来一致，盘尺寸不变）。
- `rotOf(ang)` → `rotOf(ang, rx, ry)`：用真实位置向量 `(-atan2(rx·sinAng, ry·cosAng))` 算，不直接用极角（椭圆参数角与几何方向有偏差）。端部封顶 ±72°。
- `planRing` 内两处间距估算、`layoutSeats` 里 `--rot` 都改为传 `rx, ry`。
- 牌位（`.seat-tag`）锚点公式没动，它本来就跟着 `--rot` 走，自动钉到盘朝中心那条边上。

**验证**：起静态服务器 + playwright 截图对比（旧版 / 新版、4/6/8/12/16 席、1920 与 1280 宽）。盘宽基本不变（±3% 内），无重叠、无溢出。`npm test` 109 项全过。

**最终取值**：`rotMax = 72°`（Matthew 定的）。90° 严格向心时 6 席两端盘文字完全侧躺、投屏读不出；72° 保住朝向观感、字还能斜读。**每场固定 6 人**，6 席实测转角：`72 / 64.15 / 24.39 / -24.39 / -64.15 / -72`，盘宽约 300px（1920 宽）；0° 正下方那道缝是偶数席位必然。

**临时文件**：`public/bigscreen/_preview.html|_preview.js` 已删。

## 大屏盘面重排：贴弧 + 缩尺寸 + 标签随盘转

**改了什么**：`public/bigscreen/app.js` 的席位布局整段重写，`style.css` 的桌面/标签配套改。

- **几何换基准**：原先盘心在一条独立的椭圆上、桌面椭圆（`.rim` 70%/152% 手调百分比）另算，两者不共弧 → 盘像浮在桌上。现在盘环是唯一基准，`.felt::before` / `.rim` 的椭圆由 `pushTableVars()` 按 `(rx+sw/2+rail)` 写成 `--tbl-w/h/cy`，弧线和盘环同一条曲线的平行曲线。
- **转角改外法线**：`rotOf`（指向弧心）→ `normalDeg`（`-atan2(sin/rx, cos/ry)`），盘下沿与弧线平行，才像"搁"在桌沿上，不是"插"在桌上。
- **尺寸由弧长反推**：去掉二分，`fit = 内缩弧长/(n-1)/(1+gap)` 迭代收敛；`arcTable(rx,ry,inset)` 按**盘内沿**（内缩 sw/2）算弧长——按中线等距会让相邻盘的内角顶在一起（实测 12 席端部重叠 26px）。
- **GEO 参数**（960 高约束下的实测值）：`span 74° / rotMax 66° / gap .085 / maxW .135 / maxH .32 / rail .225`。6 席实测 247px（原 ~300），12 席 127px（原 ~170）。
- **座位标签**：从 `.seat` 的兄弟节点挪进 `.pc`（跟着同一个 `transform: rotate` 转），CSS 定位 `left:50%; bottom:calc(100% + .58em)`，字体 1.35em。原先是钉在盘内上角、不转、12 席时相邻标签互相压。

**验证**：`/tmp/bs-mock.js` 假接口 + Playwright（4/8/12/16/20 席 × 1024/1366/1920/2560/3840，含窗宽动态切换）：盘面互不重叠（旋转多边形分离轴检测）、标签不压相邻盘面、不压开奖框/统计条、无 stage 裁切、盘外角始终在金线内侧。`git status` 无多余文件（误放的 `bs-mock.js` 已删）。

**注意**：盘面外角贴近金线是必然的——盘是直边、桌沿是曲线，端部切向接近竖直，123px 的角偏移落在纵向半径 662 上，归一化半径会被放大。想要"缝更宽"只调 `GEO.rail`。

## SSE 静默断链 / 半开连接 / 建连写库：根因定位与修复

**依据**：`network-test.md` + `docs/sse-diagnostics-2026-11-23.txt`（黑洞代理实测 >70s 服务端不发现、客户端 0 字节、重连 mutate 白跑、半开连接只增不减）。

**根因三条**（都在 `server.js` 与三个前端）：
1. 心跳是单向写，`write()` 成功≠送达；服务端没有任何「连接是否还活着」的判据，客户端也没有空闲超时 → 链路静默后双方都不主动结束（只能等内核 TCP 超时）。
2. 撤销 `leftAt` 写在**无条件** `store.mutate` 里 → 每次刷新都进 `withLocalLock` 串行写队列 + 一次真实写事务，而绝大多数 mutator 直接 skip。
3. 连接级 `error` 无人监听；`group` 里摘连接时不清心跳定时器（漏定时器）；进程级无兜底。

**改动**：
- `server.js`：新增 `SSE_MAX_PENDING_BYTES=1MiB` + `sseDead(res)`（destroyed / writableEnded / writableLength 超限），`sseSend` 统一判死；`sseRemoveClient`/`sseKillClient`（出组+清心跳+destroy 三合一，幂等）；广播/草稿/心跳三条写路径都走它；`needsLeaveRevoke()` 只读预检（条件与 mutator 逐条对齐，为 true 仍走 mutate 复校）；连接级 req/res error + `socket.setKeepAlive`；进程级 `uncaughtException`（传输类 EPIPE/ECONNRESET… 忽略，其余记录后 exit 1）+ `unhandledRejection`（记录后 exit 1，保持原语义）；`/healthz` 增加 `sse:{connections,groups,maxPendingBytes}`。
- 三个前端 `public/*/app.js`：`STREAM_IDLE_MS=25s`、`STREAM_WATCH_MS=5s` 空闲看门狗，`ping` 也计数，超时就 `startStream()+poll()`；`closeStream()` 清表。
- `test/sse-liveness.test.mjs`（已注册进 `test/run.mjs`）：钉死「在场重连不推进版本 / 离开后重连撤销并回首帧 / 锁定后重连不撤销」。

**验证**：`npm test` 112 项全绿；半开连接灌 1.9MB 后被回收（峰值 988KB，2.3s，group 归零）；Playwright + 黑洞代理：黑洞后 27.5s 页面自动重连，健康连接 45s 内无误重连；建连 p50 在场重连 31.3ms vs 需写事务 46.9ms。

**注意**：`/healthz` 多了一个 `sse` 字段（只增不改）；1MiB 阈值 = 对端长时间不读就断开重连，宁可重连也不要无界待发队列。
